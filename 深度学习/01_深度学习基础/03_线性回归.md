## 学习时重点盯这几处

- **训练循环的五步**（顺序不能乱）：
  1. 前向算预测 `y_hat = model(X)`
  2. 算损失 `loss = loss_fn(y_hat, y)`
  3. 反向传播 `loss.backward()`
  4. 更新参数 `optimizer.step()`
  5. **清空梯度 `optimizer.zero_grad()`** ← 最容易漏，漏了梯度会累加
- **梯度累加**：`.grad` 是**累加**不是覆盖，所以每轮必须清零 → 见 [[02.5_自动微分]]
- **为什么用平方误差 / 交叉熵**：损失函数来自**极大似然估计** → 见 [[02.6_概率]]
- **softmax 的数值稳定性**：直接 `exp` 会溢出，实现里要减去最大值
- **`nn.Linear` 帮你做了什么**：参数初始化 + 前向 + 参数注册（`parameters()` 才能被优化器看到）

## 3.1 我的理解（2026-09-29）

> 线性回归就是把用真实值和预测值的差作为一个函数，用 backward 的方法来算参数，线性可以看作一个单的神经网络层。

**逐条过**：

| 原话 | 判定 |
|---|---|
| 真实值和预测值的差作为函数 | ✅ 方向对。精确化：是**差的平方**（差会正负抵消），且最后要压成一个标量（`.mean()` / `.sum()`） |
| 用 backward 算参数 | ⚠️ **要纠正**。`backward()` 只**算梯度**，真正改参数的是 `optimizer.step()` 或手写 `w -= lr * w.grad`。只 backward 不 step，跑一万轮参数也不动 |
| 线性是单个神经网络层 | ✅ 对。D2L 3.1.4 专门讲这个：线性回归 = **单层全连接 + 无激活函数** |

**装进三件套**：

| 三件套 | 线性回归里是什么 | 将来裁缝时改哪一格 |
|---|---|---|
| 模型 | `y = Xw + b` | **换模块改这里** |
| 损失 | 平方误差 | 消融改这里 |
| 优化 | 梯度下降 + 训练循环 | 地基，改不动 |

## 3.2 从零实现（2026-09-29 学习中）

### 三件套的分工

| 名字 | 比喻 | 职责 |
|---|---|---|
| `synthetic_data` | 印卷子的 | 用**真值** w、b 造出特征和标签（含噪声） |
| `data_iter` | 发牌员 | 打乱后按 `batch_size` 分批递出去 |
| 模型（下面才写） | 学生 | 答题 → 按错题改自己 |

**关键认知**：`synthetic_data` 里的 `w`、`b` 和学习到的 `w`、`b` 是**两套东西**。
前者是**标准答案**（人为设定），后者是**学生自己学出来的**。训练就是让后者逼近前者。

### synthetic_data 逐行

```python
def synthetic_data(w, b, num_examples):  #@save
    """生成y=Xw+b+噪声"""
    X = torch.normal(0, 1, (num_examples, len(w)))   # ① 造特征:均值0,标准差1,形状(样本数,特征数)
    y = torch.matmul(X, w) + b                       # ② 算标准答案:Xw+b
    y += torch.normal(0, 0.01, y.shape)              # ③ 加噪声(模拟真实世界的误差)
    return X, y.reshape((-1, 1))                     # ④ 整理成列向量返回
```

**形状追踪**（`len(w)=2`、`num_examples=4`）：

| 步骤 | 形状 |
|---|---|
| ① `X` | `(4, 2)` = (样本数, 特征数) |
| ② `matmul(X, w) + b` | `(4,)` |
| ③ `+= 噪声` | `(4,)` |
| ④ `reshape((-1,1))` | `(4, 1)` |

**实测**（`true_w=[2.0,-3.4]`、`true_b=4.2`）：

```
features.shape = (4, 2)      labels.shape = (4, 1)
手工验算第0行: 2*1.5410 + (-3.4)*(-0.2934) + 4.2 = 8.2796
实际标签       8.2725       → 差的 0.0072 就是噪声
```

**为什么 `len(w)` 而不是写死 2**：让它和 `matmul` 自动对齐。实测：

```
len(w)=1 → X.shape=(4,1)    len(w)=3 → X.shape=(4,3)    len(w)=5 → X.shape=(4,5)
```

**裁缝含义**：模型第一层的输入维度 = 特征数。改特征就得同步改第一层。

### ⚠️ 坑：w 的形状写错会「静默广播」

```python
w = torch.randn(2, 1, requires_grad=True)   # ✅ 列向量 (2,1)
w = torch.randn(2, requires_grad=True)      # ❌ 一维 (2,)
```

一维时 `matmul(X, w)` 得到 `(100,)`，而 `y` 是 `(100,1)`，**相减不报错**，会被广播成 `(100,100)` 的垃圾矩阵：

```
错误写法: loss = 31.31   ← 完全不收敛，w 一直是 0
正确写法: loss = 0.0001  ← w 学到 [2.001, -3.399]（真值 [2.0, -3.4]）
```

**一声不响、结果全错**——所以形状必须对齐才敢信 loss。D2L 把 `w` 定义成 `(2,1)`、`y` 用 `reshape((-1,1))` 就是为这个。

### data_iter 逐行

**大白话**：它是个「发牌员」——① 数牌 ② 编号 ③ 洗牌 ④ 按张数分堆 ⑤ 一堆一堆递出。

```python
def data_iter(batch_size, features, labels):
    num_examples = len(features)              # ① 数牌:第0维长度 = 样本数
    indices = list(range(num_examples))       # ② 编号:[0,1,...,n-1]
    random.shuffle(indices)                   # ③ 洗牌(就地打乱编号,不是打乱数据)
    for i in range(0, num_examples, batch_size):   # ④ i=0,5,10... 每堆的起点
        batch_indices = torch.tensor(
            indices[i: min(i + batch_size, num_examples)])   # ⑤ 切出这一堆的编号
        yield features[batch_indices], labels[batch_indices] # ⑥ 递出:这堆题 + 这堆答案
```

**实测形状**（13 个样本、`batch_size=5`）：

```
第 1 批: (5, 2),(5, 1)    第 2 批: (5, 2),(5, 1)    第 3 批: (3, 2),(3, 1) ← 最后一批不满
```

**最后一堆靠 `min()` 兜住**（不写也行，Python 切片本身会自动截断，`min` 只是让意图更明确）。

### 为什么必须 shuffle

| 实验 | 不 shuffle | shuffle |
|---|---|---|
| **线性数据**（凸问题） | acc 0.998 | acc 0.998 ← **无差别** |
| **非线性数据 + MLP** | acc **0.755** | acc **0.851** |
| 其中第 1 轮 | acc **0.500**（等于瞎猜） | acc 0.847 |

**原因**：数据按类别排好序时，`batch_size=10` → **连续 50 批全是同一类**，模型被推着来回横跳，走不到谷底。

**结论**：第 3 章不 shuffle 也能跑（加法交换律 + 凸问题）；**第 4 章 MLP 开始就是刚需**。
D2L 在 3.2 就写上，是因为这段代码要一路抄到后面。

### Python 语法小抄（读代码卡住时回来查）

| 写法 | 大白话 | 实测 |
|---|---|---|
| `len(x)` | 数长度（对张量 = 第 0 维） | `len([10,20,30])` → `3` |
| `range(a,b,s)` | 生成一串数字的**规则**，不是列表 | `range(5)` → `range(0,5)` |
| `list(range(5))` | 套上 `list()` 才是真列表 | → `[0,1,2,3,4]` |
| `min(a,b)` | 取小的 | `min(13,10)` → `10` |
| `random.shuffle(a)` | **就地**打乱，**返回 None** | `a` 变了，返回值是 `None` |
| `b[i:j]` | 切一段；越界不报错 | `b[3:99]` → 自动截断 |
| `yield` | 交一个、暂停、记住现场 | 见下 |

**⚠️ `shuffle` 的坑**：它**不返回新列表**，所以绝不能写 `indices = random.shuffle(indices)`——那样 `indices` 会变成 `None`。正确写法是**单独一行调用**。

### yield vs return

| | `return` | `yield` |
|---|---|---|
| 调用时 | 立刻从头跑到底 | **一行都不执行** |
| 交几次 | 1 次，交完函数结束 | 多次，每次暂停 |
| 交完后 | 下次调用重来 | **停在原地，局部变量全记住** |

**内存实测**：造 100 万个，列表占 **8.4 MB**，生成器占 **208 字节**（且与 N 无关）。

**这就是为什么 `data_iter` 用 `yield`**：数据集再大也不会撑爆内存。

### 迭代器要点（配合 `yield` 理解）

- **可迭代对象**（列表）能 `for`；**迭代器**多一个 `__next__`，`iter(列表)` 才能得到
- `next(指针)` 往前走一步并取值；走到头报 `StopIteration`
- `for` 背后就是 `iter()` → 反复 `next()` → 收到 `StopIteration` 结束
- **⚠️ 迭代器只能走一遍**（指针到头不回头）：

```python
g = data_iter(10, features, labels)
for Xb, yb in g: ...   # 正常
for Xb, yb in g: ...   # ❌ 一次都不执行,也不报错
```

**正确做法**：要么**重新调用** `data_iter(...)`，要么直接写进 `for` 里。
`DataLoader` 每个 epoch 自动新建迭代器，所以能反复用。
