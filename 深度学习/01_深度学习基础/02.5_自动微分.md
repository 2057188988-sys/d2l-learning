# 2.5 自动微分

**状态**：🔄 部分接触（已经跑过 `backward()`，原理未展开）

**一句话**：上一节讲的梯度，**不需要手算**——只要告诉 PyTorch「谁需要梯度」，它会自动算好放在 `.grad` 里。

---

## 一、三个必备要素

```python
import torch

x = torch.arange(4.0, requires_grad=True)   # ① 声明「我要对它求导」
y = 2 * torch.dot(x, x)                     # ② 定义一个标量输出
y.backward()                                # ③ 触发反向传播
print(x.grad)                               # tensor([ 0.,  4.,  8., 12.])
```

| 要素 | 作用 |
|---|---|
| `requires_grad=True` | 声明这个张量需要被求导（**不写就没有 `.grad`**） |
| 计算过程 | 前向计算，PyTorch 在背后**悄悄记录计算图** |
| `y.backward()` | 沿计算图反向走一遍，把梯度算出来 |
| `x.grad` | 结果存在这里 |

**这就是「自动微分」**：你只管写前向计算，求导交给框架。

---

## 二、计算图：PyTorch 在背后记了什么

```python
x = torch.arange(4.0, requires_grad=True)
y = 2 * torch.dot(x, x)
```

PyTorch 内部记下了一条链：

```
x  ──dot──→  u  ──×2──→  y
```

`backward()` 就是沿着这条链**从右往左**，用链式法则一层层乘回去——这就是「**反向**传播」这个名字的来历。

> **关键**：只有 `requires_grad=True` 的张量参与的运算**才会被记录**。所以如果你中途用了 `.detach()` 或者 `.numpy()`，链就断了。

---

## 三、非标量输出：为什么必须传 gradient

```python
x = torch.arange(4.0, requires_grad=True)
y = x * x                     # y 是向量，不是标量
y.backward()                  # ❌ RuntimeError
```

报错大意是「grad 只能为标量隐式创建」。

**原因**：梯度是「**标量**对变量的导数」。`y` 是向量时，`∂y/∂x` 会是一个矩阵（雅可比），PyTorch 不知道该压缩成什么。

**两种解决办法**：

```python
# 办法 1：先求和变成标量（最常用）
y.sum().backward()

# 办法 2：手动传一个和 y 同形的权重
y.backward(torch.ones_like(y))
```

> **实践中的规律**：损失函数**永远是标量**（一个数）。这就是为什么 `loss.backward()` 不会报错——设计上就保证了。

---

## 四、`.detach()`：切断梯度链

```python
u = y.detach()      # u 和 y 数值相同，但不再参与梯度计算
```

**用途**：想让某个张量「只当常数用」，不参与求导。

```python
# 例子：更新参数时不希望这一步被记进计算图
with torch.no_grad():
    w -= lr * w.grad
```

**`torch.no_grad()` 和 `.detach()` 的区别**：

| | 作用范围 | 场景 |
|---|---|---|
| `.detach()` | 单个张量 | 把某个张量当常数 |
| `torch.no_grad()` | 一个代码块 | 整段都不记录（评估、手动更新参数） |

---

## 五、为什么每轮要 `zero_grad()`

```python
for epoch in range(10):
    loss = compute_loss(...)
    loss.backward()          # 梯度会累加！
    optimizer.step()
    optimizer.zero_grad()    # 清空，准备下一轮
```

**PyTorch 的 `.grad` 是累加的（`+=`），不是覆盖的。**

如果不清零，第二轮算出来的梯度会**加上**第一轮的，参数更新幅度越来越大，训练直接崩掉。

> 这是新手最经典的 bug 之一：**loss 不降反升、或者几天后突然爆炸**，第一件事就检查有没有漏掉 `zero_grad()`。
