## 一、三个必备要素

```python
import torch

x = torch.arange(4.0, requires_grad=True)   # ① 声明「我要对它求导」
y = 2 * torch.dot(x, x)                     # ② 定义一个标量输出
y.backward()                                # ③ 触发反向传播
print(x.grad)                               # tensor([ 0.,  4.,  8., 12.])
```

| 要素 | 作用 |
|---|---|
| `requires_grad=True` | 声明这个张量需要被求导（**不写就没有 `.grad`**） |
| 计算过程 | 前向计算，PyTorch 在背后**悄悄记录计算图** |
| `y.backward()` | 沿计算图反向走一遍，把梯度算出来 |
| `x.grad` | 结果存在这里 |

**这就是「自动微分」**：你只管写前向计算，求导交给框架。

### 两处容易卡住的细节（2026-09-29 补充）

**① `arange(4.0)` 里的 `.0` 不能省**

```python
torch.arange(4)      # tensor([0, 1, 2, 3])      dtype = torch.int64
torch.arange(4.0)    # tensor([0., 1., 2., 3.])  dtype = torch.float32
```

值一样，**类型不一样**。而**整数张量禁止求导**：

```
RuntimeError: only Tensors of floating point dtype can require gradients
```

原因：梯度天然是小数（0.5、0.001），整数存不下，PyTorch 干脆禁止。所以这条链要记牢：
**要 `requires_grad=True` → 张量必须是浮点 → 写 `4.0` 不写 `4`**。

打印出来带小数点（`1.`）就是在提醒你「这是浮点」，`1.` 和 `1.0` 是一回事。

**② `torch.dot(x, x)` 是什么**

点积：**同长度向量逐元素相乘再求和 → 一个标量**。定义见 [2.3.7 点积](https://zh.d2l.ai/chapter_preliminaries/linear-algebra.html) → 本地笔记 [[02.3_线性代数]]

```python
x = torch.arange(4.0)   # [0., 1., 2., 3.]
torch.dot(x, x)         # 0*0 + 1*1 + 2*2 + 3*3 = 14.0  → 标量
```

`dot(x, x)` 就是各元素平方和 = ‖x‖²，所以 `y = 2·dot(x, x) = 2(x₁²+x₂²+x₃²+x₄²)`，导数 $\partial y/\partial x_i = 4x_i$，也就是 `[0, 4, 8, 12]`——和 `x.grad` 打印的结果对上。

| 写法 | 做什么 | 结果形状 |
|---|---|---|
| `x * y` | 逐元素相乘（Hadamard 积） | `(4,)` → `(4,)` **不变** |
| `torch.dot(x, y)` | 逐元素相乘**再求和** | `(4,)` → **标量** |

> `torch.dot` **只吃一维张量**，传矩阵直接报错；矩阵/批量用 `@` 或 `torch.matmul`。

## 二、计算图：PyTorch 在背后记了什么

```python
x = torch.arange(4.0, requires_grad=True)
y = 2 * torch.dot(x, x)
```

PyTorch 内部记下了一条链：

```
x  ──dot──→  u  ──×2──→  y
```

`backward()` 就是沿着这条链**从右往左**，用链式法则一层层乘回去——这就是「**反向**传播」这个名字的来历。

> **关键**：只有 `requires_grad=True` 的张量参与的运算**才会被记录**。所以如果你中途用了 `.detach()` 或者 `.numpy()`，链就断了。

---

## 三、非标量输出：为什么必须传 gradient

```python
x = torch.arange(4.0, requires_grad=True)
y = x * x                     # y 是向量，不是标量
y.backward()                  # ❌ RuntimeError
```

报错大意是「grad 只能为标量隐式创建」。

**原因**：梯度是「**标量**对变量的导数」。`y` 是向量时，`∂y/∂x` 会是一个矩阵（雅可比），PyTorch 不知道该压缩成什么。

**两种解决办法**：

```python
# 办法 1：先求和变成标量（最常用）
y.sum().backward()

# 办法 2：手动传一个和 y 同形的权重
y.backward(torch.ones_like(y))
```

> **实践中的规律**：损失函数**永远是标量**（一个数）。这就是为什么 `loss.backward()` 不会报错——设计上就保证了。

## 四、`.detach()`：切断梯度链

**一句话**：数值照抄，**梯度线剪断**。类比 Excel 的「粘贴为数值」——数字还是那个数字，但公式没了，源数据再变它也不动。

### 最小例子（跑过，就是这个输出）

```python
x = torch.tensor([1., 2., 3.], requires_grad=True)
y = x * 2
u = y.detach()
```

```
y = tensor([2., 4., 6.], grad_fn=<MulBackward0>)   ← 记着自己是怎么来的
u = tensor([2., 4., 6.])                           ← 只是数字，什么也不记

y.requires_grad = True  | y.grad_fn = <MulBackward0>   ← 有线
u.requires_grad = False | u.grad_fn = None             ← 没线
```

**数值一模一样，唯一区别是 `grad_fn`。** 线断了会怎样：

```python
y.sum().backward()   # ✅ x.grad = tensor([2., 2., 2.])
u.sum().backward()   # ❌ RuntimeError: element 0 of tensors does not
                     #    require grad and does not have a grad_fn
```

### D2L 2.5.3 的验证例子：`x.grad == u`

```python
x.grad.zero_()
y = x * x
u = y.detach()      # 把 y 当常数
z = u * x
z.sum().backward()
x.grad == u         # tensor([True, True, True, True])
```

`z = u * x` 里 `u` 已经是死数字（常数），所以 $dz/dx = u = x^2$。

**不 detach 的对照**（实测）：

| 写法 | z 等于什么 | dz/dx | 实测 x.grad |
|---|---|---|---|
| `z = u * x`（detach 过） | u 视为常数 | $u = x^2$ | `[0., 1., 4., 9.]` |
| `z = y * x`（没 detach） | $x^3$ | $3x^2$ | `[0., 3., 12., 27.]` |

**链断没断，直接改变导数的值。** 难的不是 `detach`，是 D2L 那个例子用了复合函数——先看上面的最小例子就顺了。

### 用途

想让某个张量「只当常数用」，不参与求导。

```python
# 例子：更新参数时不希望这一步被记进计算图
with torch.no_grad():
    w -= lr * w.grad
```

**最常用的场景**：`x.detach().numpy()` —— 带梯度的张量**直接调 `.numpy()` 会报错**，必须先 `detach()`。

### `torch.no_grad()` 和 `.detach()` 的区别

| | 作用范围 | 场景 |
|---|---|---|
| `.detach()` | 单个张量 | 把某个张量当常数 |
| `torch.no_grad()` | 一个代码块 | 整段都不记录（评估、手动更新参数） |

## 五、为什么每轮要 `zero_grad()`

```python
for epoch in range(10):
    loss = compute_loss(...)
    loss.backward()          # 梯度会累加！
    optimizer.step()
    optimizer.zero_grad()    # 清空，准备下一轮
```

**PyTorch 的 `.grad` 是累加的（`+=`），不是覆盖的。**

如果不清零，第二轮算出来的梯度会**加上**第一轮的，参数更新幅度越来越大，训练直接崩掉。

**真实对照实验**（拟合 `Y = 3X + 2`，lr = 0.05，跑 30 轮）：

| 写法 | 30 轮后 w（真值 3） | 最后 loss |
|---|---|---|
| 有 `zero_grad()` | 3.19 | 0.0537 |
| **漏掉** `zero_grad()` | **4.9182**（越滚越大，`w.grad` 已达 -56.85） | 发散 |

> 这是新手最经典的 bug 之一：**loss 不降反升、或者几天后突然爆炸**，第一件事就检查有没有漏掉 `zero_grad()`。

## 六、必会 6 个 API（速查表）

按训练循环的位置排，**这 6 个会写，2.5 就算过关**。

| 位置 | API | 必须记住的一句 |
|---|---|---|
| 建参数 | `torch.tensor(..., requires_grad=True)` | 不写 → 没有 `.grad`；且必须是**浮点** |
| 求导 | `loss.backward()` | `loss` 必须是**标量**（向量先 `.sum()`） |
| 取梯度 | `w.grad` | 形状和 `w` 一样 |
| 更新 | `optimizer.step()` | 交给 optimizer，**不手写** `w -= lr*w.grad` |
| **清零** | `optimizer.zero_grad()` | **漏了必崩**（见第五节实测） |
| 评估 | `with torch.no_grad():` | 只算数值不记图，省显存 |
| 取值 | `x.detach().numpy()` | 转 numpy 前必须先 `detach` |

### 六个一起用的完整例子（实测输出）

```python
torch.manual_seed(0)
w = torch.tensor(0.0, requires_grad=True)
b = torch.tensor(0.0, requires_grad=True)
X = torch.tensor([1., 2., 3., 4.]);  Y = 3 * X + 2      # 真值 w = 3, b = 2
opt = torch.optim.SGD([w, b], lr=0.05)

for epoch in range(30):
    y_hat = w * X + b
    loss = ((y_hat - Y) ** 2).mean()
    loss.backward()        # ② 求导
    opt.step()             # ④ 更新
    opt.zero_grad()        # ⑤ 清零
```

```
30 轮后 w = 3.19  b = 1.4415   (真值 3, 2)
最后 loss = 0.053688
```

## 七、控制流：if/while 也能求导（2.5.4，可跳）

> **本节按裁缝路线可跳**。只留一句话结论，够用即可。

**结论**：PyTorch 是**边跑边记**的，所以代码里写 `if` / `while` / 函数调用（= **控制流**）照样能求导。换个输入走了另一条分支，梯度就按**实际走过的那条路**算。

最小验证（实测）：

```python
def g(x):
    if x > 0: return x * 3
    else:     return x * 100

g(torch.tensor( 2.0, requires_grad=True))   # →   6.0，梯度 3
g(torch.tensor(-2.0, requires_grad=True))   # → -200.0，梯度 100
```

**同一个函数，输入符号不同 → 走的分支不同 → 梯度完全不同（3 和 100）。**

D2L 的 `f(a)` 例子（含 `while` 翻倍 + `if` 分支）里还有一段「分段线性」的推导和 `a.grad == d / a` 的验证。**那属于实现层细节，看不懂也不影响第 3 章**，需要时再回来看官网 [2.5.4](https://zh.d2l.ai/chapter_preliminaries/autograd.html)。

**为什么课程要专门讲这个？** 因为部分框架要求先把模型写成静态图，`if`/`while` 根本没法提前画出来；PyTorch 动态图不用。
