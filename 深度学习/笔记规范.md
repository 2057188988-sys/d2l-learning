# 笔记规范

写笔记的规则。**目的不是「记得漂亮」，是「一个月后自己还看得懂、面试时能拿它讲三分钟」。**

---

## 一、每个知识点的固定模板

不是每节都要写全，但**「踩的坑」这一栏别省**——它是最容易被忽略、却最值钱的部分。

```markdown
### 2.3.1 梯度的定义

**一句话**
偏导数排成的向量，指向函数增长最快的方向。

**为什么需要它**
参数更新要用：w = w - lr * w.grad

**关键代码**
x = torch.tensor([1., 2., 3.], requires_grad=True)
((x ** 2).sum()).backward()
x.grad    # tensor([2., 4., 6.])  即 2x

**踩的坑**
书上写 ∂y/∂x 是 (4,1)，PyTorch 的 x.grad 是 (4,)。
原因：数学书写列向量是为了矩阵乘法对齐，一维张量不区分行列。
记法：看到 ᵀ 不用慌，只是「摆正姿势」，不影响数值。

**待确认**
非标量 y 调 backward() 为什么要传 gradient 参数？（2.5 节解答）
```

**四个模块的作用**

| 模块 | 作用 |
|---|---|
| 一句话 | 复习时只扫这一行就够 |
| 为什么需要它 | 防止「背了但不知道干嘛用」 |
| 关键代码 | 能直接跑，不写伪代码 |
| **踩的坑** | **面试素材 + 防止重踩** |
| 待确认 | 把疑问显式记下来，学到后面回来补 |

## 二、文件组织规则

**1. 文件名 = 编号 + 章节名，不要起花名。**

```
✅ 02.1_数据操作.md
❌ 张量操作那些事.md
```

理由：编号自带顺序，文件列表天然就是学习顺序；以后搜 `02.3` 能直接定位。

**2. 一节的笔记写在一个文件里。**

写不下就说明这节内容确实多，可以拆成 `02.3_微积分.md` + `02.3.1_导数的直观理解.md`。

**3. 概念之间用 `[[]]` 互链。**

```markdown
梯度见 [[02.3_微积分]]
```

链接多了，Obsidian 的**关系图谱**才会变成一张真正的知识网——复习时顺着链接能回溯，比翻目录快得多。

**4. 代码块必须标语言。**

写 ```python 而不是 ```，否则没有高亮。

**5. 文件名不带日期，日期写在标题里。**

```
✅ 02.1_数据操作.md          →  内容标「（2026-09-21 记录）」
❌ 数据操作_20260921.md
```

理由：一个文件会**长期反复追加**，日期进文件名会让它每次都得改名；日期进标题既保留时间信息，又不影响文件长期复用。

## 三、什么值得记

| 值得记 | 不值得记 |
|---|---|
| 报错信息 + 原因 + 解决 | 完整抄一遍书上的定义 |
| 自己的理解（哪怕不严谨） | 教材原话复制粘贴 |
| 参数改了之后结果怎么变 | 只写「跑通了」 |
| 和已有知识的联系 | 无来源的结论 |
| 想不通的地方 | 「以后再说」 |

**判断标准**：这条记录，**一个月后我还能看懂吗？面试时能拿它讲三分钟吗？** 能就记。

## 四、从「抄书」升级到「自己的东西」

这是笔记有没有价值的**分水岭**。

```
学  →  记  →  改  →  比  →  上传
              ↑        ↑
          容易停下   真正值钱
```

大部分人停在「记」——跟着视频敲通，写几句说明，就觉得学完了。

**真正拉开差距的是「改」和「比」**：

| 动作 | 怎么做 | 例子 |
|---|---|---|
| **改** | 换个数据 / 换个模块 / 换个参数 | 把 SGD 换成 Adam |
| **比** | 做对照，用表格记结果 | 见下面的格式 |

**对比实验的记录格式**（这是可以直接写进简历的素材）：

```markdown
### 实验：线性回归的优化器对比

| 优化器 | 学习率 | 10 轮后 loss |
|---|---|---|
| SGD  | 0.03 | 0.2451 |
| Adam | 0.01 | 0.0003 |

**结论**：Adam 收敛快得多，但在本例中最终精度略低于调好的 SGD。
**为什么**：Adam 有自适应学习率，前期步子大……
**我的想法**：小数据 + 简单模型上，调好的 SGD 未必输。
```

**「结论」和「我的想法」是关键**——有这两栏，这段就是「你的东西」；没有，就只是操作记录。
